# 全局选中翻译应用设计稿

## 目标
做一个 Android 手机翻译应用，核心能力是：

- 在其他应用中选中文字后直接触发翻译
- 翻译结果不遮挡原文
- 默认英译中
- 速度快，准确率高
- 联网优先，离线兜底
- 提供常见翻译软件的基础能力
- 提供下拉快捷入口，可配置常用功能

## 约束
- 面向 vivo S60 的 Android 环境
- 全局选中文本场景优先
- 需要无障碍服务能力
- 不依赖“先复制再翻译”作为主流程
- 结果展示必须尽量避开原文区域
- 目录结构必须分层清晰，便于长期维护

## 产品范围
### 必做
- 全局选中文本捕获
- 文本翻译
- 翻译浮层展示
- 历史记录
- 收藏
- 复制译文
- 朗读译文
- 快速切换开关
- 下拉快捷入口

### 先不做
- 多端账号同步
- 社交分享社区
- 复杂排版编辑器
- 大模型长文总结

## 核心交互
1. 用户在任意应用中选中文本
2. 应用通过无障碍服务识别文本
3. 译文请求发送到翻译引擎
4. 结果以底部卡片或侧边浮层展示
5. 原文保持在当前应用内，不被覆盖
6. 用户可复制、收藏、朗读、重试

## 翻译策略
### 主策略
- 默认接入国内云翻译 API
- 优先选择稳定、延迟低、支持中英双向的服务
- 支持失败自动切换备用引擎

### 建议优先级
1. 主引擎：百度翻译或有道智云
2. 备引擎：讯飞翻译
3. 兜底：本地缓存和短句离线包

### 加速手段
- 最近翻译缓存
- 常用短句缓存
- 术语表本地缓存
- 并发超时控制
- 失败自动降级

## 参考能力对标
常见翻译软件通常会提供这些能力，本项目按实用优先级纳入：

- 文本翻译
- 语种自动识别
- OCR 图片翻译
- 语音朗读
- 历史记录
- 收藏夹
- 词典/术语
- 复制结果
- 离线翻译
- 快捷入口

## 技术架构
### App 层
- `app/`：启动入口、主题、导航、权限引导

### 核心层
- `core/permissions/`：无障碍、悬浮窗、通知等权限状态
- `core/network/`：API 客户端、超时、重试、签名
- `core/storage/`：缓存、历史、收藏、设置
- `core/ui/`：通用组件、图标、颜色、浮层基座

### 功能层
- `features/selection/`：选中文本捕获
- `features/translate/`：翻译编排、引擎切换、语言识别
- `features/overlay/`：译文浮层展示
- `features/shortcuts/`：下拉快捷入口
- `features/history/`：历史记录
- `features/favorites/`：收藏
- `features/offline/`：离线包管理
- `features/ocr/`：后续图片翻译预留

### 数据层
- `data/providers/`：百度、有道、讯飞等翻译适配器
- `data/cache/`：翻译结果缓存
- `data/repository/`：统一数据访问入口

## 选中文本处理
- 监听无障碍事件
- 提取当前焦点控件文本或选区文本
- 对不可直接提取的场景提供兜底策略
- 对长文本自动分段翻译
- 对重复文本直接命中缓存

## 浮层规则
- 默认出现在屏幕底部或侧边
- 不覆盖当前文本主体
- 支持拖动、收起、展开
- 支持复制、收藏、朗读、重试
- 支持手动关闭

## 下拉快捷入口
可配置的快捷项建议包括：

- 实时翻译
- 历史
- 收藏
- 离线模式
- OCR 翻译
- 术语库
- 设置

## 错误处理
- 网络失败时自动切换备用引擎
- 所有引擎失败时提示重试
- 权限未开启时给出明确引导
- 无法获取选中文本时显示降级提示
- 离线包不存在时提示下载

## 测试范围
- 选中文本捕获测试
- 多应用场景测试
- 浮层遮挡测试
- 引擎切换测试
- 缓存命中测试
- 离线兜底测试
- 快捷入口可用性测试

## 目录原则
- 一个目录只放一个职责域
- 通用能力放 `core/`
- 业务功能放 `features/`
- API 适配放 `data/providers/`
- 文档放 `docs/`
- 不把所有代码平铺在同级目录
